# ADR Guide

Architectural Decision Records capture structural decisions that should outlive individual commits or conversations.

## When to Write an ADR

Write an ADR when a change affects:

- module boundaries,
- canonical behavior semantics,
- build, test, or release workflows,
- or a long-lived project constraint.

## Format

Use one file per decision named `NNNN-short-title.md`.

Required sections:

- Context
- Decision
- Consequences
- Alternatives Considered

Start from [TEMPLATE.md](TEMPLATE.md).
